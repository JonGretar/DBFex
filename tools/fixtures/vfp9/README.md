# Visual FoxPro 9 fixture generator

This directory contains a deterministic evidence probe for Visual FoxPro 9
binary and variable-width field storage. It is not part of the normal test or CI
suite.

## Running

Run the manually triggered **Generate Visual FoxPro 9 fixture** GitHub Actions
workflow. The workflow:

1. downloads the VFPX archive of Microsoft's Visual FoxPro 9 SP2 OLE DB
   Provider from a pinned repository revision;
2. verifies the installer's pinned SHA-256 and Microsoft Authenticode signature;
3. installs it on an ephemeral Windows runner;
4. executes `generate.ps1` in 32-bit PowerShell; and
5. uploads the unreviewed output as a short-lived workflow artifact.

The workflow never commits generated files.

## Intended evidence

The generator asks VFPOLEDB to create a free table containing:

- Varchar (`V`);
- Varbinary (`Q`);
- binary Character (`C NOCPTRANS`);
- binary Memo (`M NOCPTRANS`);
- Blob (`W`);
- Double (`B`);
- nullable fields and an Integer identifier.

Records exercise short and full-width binaries, significant trailing bytes,
empty values, explicit nulls, multi-block memo/blob payloads, and a deleted
record. The artifact also contains:

- `expected-values.json`, derived from the exact values sent to the producer;
- `observed-structure.json`, a minimal producer-output inventory;
- the provider version; and
- `sha256.txt`.

Generation is deliberately allowed to fail if VFPOLEDB does not support one of
these DDL or value operations. Such a failure is evidence about the provider's
limits; do not weaken the script by hand-constructing the missing bytes. Each
operation is labeled in the workflow log, and partially generated files are
uploaded even when a later operation fails.

## Acceptance before adding fixtures

Do not copy an artifact into `test/dbf_files/` until all of the following are
reviewed:

- provider identity and version;
- emitted DBF version byte, especially `0x42` versus `0x32`;
- descriptor types, widths, and flags;
- record bitmap allocation and stored-length bytes;
- FPT pointer, block type, and payload behavior for binary Memo and Blob;
- exact values and null/empty/deleted distinctions;
- redistribution terms for files generated by the Microsoft provider; and
- cross-check results from at least one independent mature reader.

General/OLE (`G`) is intentionally absent. Creating a meaningful General value
requires an OLE object producer and should be handled by a separate VFP9
application-generated fixture. Do not infer its FPT type-2 behavior from this
provider probe.
